# 문서 작성 규칙 (Doc Writing Rules) — DevOps

Claude가 이 저장소에서 문서를 작성하거나 수정할 때 반드시 따라야 할 규칙.

---

## 1. 언어 및 문체

- **기본 언어**: 한국어
- **영어 원문 병기**: 기술 용어는 첫 등장 시 반드시 영어 원문 병기
  - 예: 컨테이너 레지스트리 (Container Registry), 파이프라인 (Pipeline)
- **문체**: 명사형 종결 (`~임`, `~사용`, `~필요`)
  - 금지: `~입니다`, `~합니다`, `~할 수 있습니다`
- **존댓말 금지**: 기술 문서 특성상 경어체 사용하지 않음
- **단정적 표현**: 추측성 표현 금지 (`~일 것임`, `~할 수도 있음`)

## 2. 코드 블록

- **언어 태그 필수**: 모든 코드 블록에 언어 지정
  ```bash    # shell commands, AWS CLI
  ```hcl     # Terraform
  ```yaml    # GitHub Actions, Kubernetes, Helm
  ```python  # Python scripts
  ```json    # JSON configs
  ```
- **실행 가능한 코드**: 복붙해서 바로 실행되는 수준으로 작성
- **플레이스홀더 표시**: 교체 필요한 값은 `<YOUR_VALUE>` 형식으로 명시
  - 예: `<ACCOUNT_ID>`, `<CLUSTER_NAME>`, `<YOUR_ORG>`, `<APP_NAME>`
- **리전 기본값**: `ap-northeast-2` 사용
- **주석 필수**: 복잡한 코드는 한국어 주석으로 설명

## 3. 섹션 구성 필수 요소

새 문서는 반드시 아래 5개 섹션을 포함해야 함:

| 섹션 | 내용 | 생략 가능 여부 |
|------|------|----------------|
| 1. 개요 | 무엇인지, 왜 필요한지, 다른 방식과 비교표 | 불가 |
| 2. 설명 | 원리, 코드, Best Practice | 불가 |
| 3. 트러블슈팅 | 증상 → 원인 → 해결 | 불가 |
| 4. 모니터링 및 알람 | CloudWatch 지표/알람, 파이프라인 모니터링 | 불가 |
| 5. TIP | 현장 팁, 관련 문서 링크 | 가능 |

## 4. DevOps 문서 특성 반영

- **파이프라인 플로우**: 주요 문서에 ASCII art 다이어그램 포함
- **보안 우선**: 모든 코드 예시에 최소 권한 원칙 적용
- **환경 분리**: dev/staging/prod 환경별 차이 명시
- **자동화**: 수동 절차보다 자동화 방법 우선 기술
- **재현성**: 동일한 코드로 동일한 결과 보장

## 5. 코드 예시 기준값

| 항목 | 기준값 |
|------|--------|
| AWS 리전 | `ap-northeast-2` |
| Terraform provider | `~> 5.0` |
| GitHub Actions runner | `ubuntu-latest` |
| ArgoCD 버전 | `v2.x` |
| EKS 버전 | `1.29+` |
| Helm 버전 | `v3.x` |
| Python 버전 | `3.11+` |

## 6. 표 작성 규칙

- 비교 정보는 반드시 표(table)로 정리
- 3개 이상의 항목을 나열할 때는 불릿 대신 표 사용
- 헤더는 굵게 표시 불필요 (마크다운 헤더가 자동 처리)
- 빈 셀 허용하지 않음 (해당 없으면 "N/A" 또는 "-")

## 7. 트러블슈팅 작성 형식

```markdown
### 증상 N: {증상 제목}

{실제 에러 메시지나 현상을 코드블록으로}

**원인**: 왜 발생하는지 근본 원인 설명

**해결 방법**:
```bash
# 해결 명령어
```
```

## 8. 관련 문서 링크 형식

각 문서 마지막 TIP 섹션에 관련 문서 링크 포함:

```markdown
**관련 문서**
- [문서 제목](상대 경로.md)
- [문서 제목](../다른카테고리/문서.md)
```

## 9. 금지 사항

- 추측성 내용 작성 금지 (실제 경험 기반만)
- "~할 수 있습니다", "~일 것입니다" 같은 불확실한 표현 금지
- 공식 문서 링크 없이 수치(비용, 한도) 단독 기재 금지
- `latest` 태그 이미지 예시에 사용 금지 (항상 특정 버전 명시)
- Access Key를 코드 예시에 하드코딩 금지 (OIDC 또는 플레이스홀더 사용)
